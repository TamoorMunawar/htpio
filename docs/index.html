package:htpio · v1.2.0 · MIT

The easy HTTP client for Flutter

Simple requests, typed JSON, interceptors, retry, token refresh, caching, an offline queue, uploads, downloads and mocking, all in one package. Every class and function is on this page with an example you can copy.

Getting started

Install

Add htpio to your Flutter app, then import it. One import gives you everything.

Your first request

Create one client for your whole app and reuse it. It keeps connections open, which makes later requests faster.

Typed models

Give htpio your model’s fromJson and res.data becomes that model.

Recommended app structure

Keep one client in a single file and put each endpoint in an API class. Widgets call the API class and never build URLs themselves.

HtpioClient

HtpioClient()constructor

HtpioClient({
  String baseUrl = '',
  Map<String, String>? headers,
  Map<String, dynamic>? queryParameters,
  Duration? timeout,
  bool Function(int statusCode)? validateStatus,
  http.Client? httpClient,
  HtpioCache? cache,
  MockServer? mockServer,
  List<HtpioInterceptor>? interceptors,
})

Creates the client. Every argument is optional.

ParameterTypeWhat it does
baseUrlStringJoined to relative paths. '/users' becomes baseUrl + '/users'. Full URLs are used as is.
headersMap<String, String>Sent with every request. Per-request headers win.
queryParametersMap<String, dynamic>Added to every request URL.
timeoutDuration?Default time limit for a whole request. null means no limit.
validateStatusbool Function(int)Which status codes count as success. Default: 200–299. Others throw HtpioError.
httpClienthttp.ClientCustom transport. Pass a MockClient in unit tests.
cacheHtpioCache?Used by requests made with cache: true.
mockServerMockServer?When enabled, answers matching requests without the network.
interceptorsList<HtpioInterceptor>Same as calling addInterceptor for each.

get()GET

Future<HtpioResponse<T>> get<T>(
  String path, {
  Map<String, dynamic>? queryParameters,
  Map<String, String>? headers,
  T Function(Map<String, dynamic>)? fromJson,
  T Function(dynamic data)? decoder,
  ResponseType responseType = ResponseType.json,
  CancelToken? cancelToken,

Fetches data. The response body is decoded for you.

ParameterTypeWhat it does
pathStringPath joined to baseUrl, or a full URL.
queryParametersMap<String, dynamic>{'page': 2} → ?page=2. A list repeats the key; null values are skipped.
headersMap<String, String>Extra headers for this request only.
fromJsonT Function(Map)Turns a JSON object into your model.
decoderT Function(dynamic)Turns any decoded body (list, string…) into T. Use it for lists.
responseTypeResponseTypejson (default), plain for a String, bytes for a Uint8List.
cancelTokenCancelToken?Lets you cancel the request.
timeoutDuration?Overrides the client timeout.
cacheboolServe from the client’s HtpioCache when possible.
extraMap<String, dynamic>Values for your own interceptors to read.

Fetches only the headers, for example to check a file’s size before downloading it.

request()ANY

Future<HtpioResponse<T>> request<T>(
  String path, {
  String method = 'GET',
  Object? data,
  ...same as get()
})

Sends a request with any HTTP method. All the verb methods above call this one.

send()method

Future<HtpioResponse<T>> send<T>(HtpioRequest<T> request)

Sends a request object you built yourself. Interceptors use it to send a request again.

addInterceptor() / removeInterceptor()method

void addInterceptor(HtpioInterceptor interceptor)
bool removeInterceptor(HtpioInterceptor interceptor)
List<HtpioInterceptor> get interceptors

Adds or removes an interceptor. Requests pass through interceptors in the order they were added, and responses pass through in reverse order.

use()method

void use(HtpioMiddleware middleware)

Adds a middleware, for example OfflineMode.

close()method

void close()

Closes open connections. Call it when the client is no longer needed, for example in a test’s tearDown. A closed client can’t send requests.

Sending data

How data is encodedguide

Pass any of these as data. htpio picks the encoding and sets the Content-Type header.

You passSent as
Map, List, object with toJson()JSON · application/json
FormDataFile upload · multipart/form-data
StringText, unchanged · text/plain unless you set a type
List<int> / Uint8ListRaw bytes · application/octet-stream
Map + header content-type: application/x-www-form-urlencodedForm fields · a=1&b=2

FormDataclass

FormData()
factory FormData.fromMap(Map<String, dynamic> map)
final Map<String, String> fields
final List<MapEntry<String, HtpioMultipartFile>> files

A file-upload body (multipart/form-data). In fromMap, HtpioMultipartFile values (or lists of them) become files and every other value is sent as text. You can send the same form again; files are re-read each time, so retries work.

HtpioMultipartFileclass

HtpioMultipartFile.fromPath(String path, {String? filename, String? contentType})
HtpioMultipartFile.fromBytes(List<int> bytes, {String? filename, String? contentType})
HtpioMultipartFile.fromString(String value, {String? filename, String? contentType})

One file inside a FormData. fromPath reads from disk and works on mobile and desktop. On the web there are no file paths, so use fromBytes (for example with bytes from a file picker).

ParameterTypeWhat it does
filenameString?Name the server sees. Defaults to the file’s name for fromPath.
contentTypeString?MIME type, e.g. image/png.

Responses

HtpioResponse<T>class

final T data
final int statusCode
final Map<String, String> headers
final HtpioRequest? request
final String? reasonPhrase
bool get isSuccess

What every request returns.

ParameterTypeWhat it does
dataTThe body: decoded JSON, a String, bytes, or your model.
statusCodeinte.g. 200, 201, 204.
headersMap<String, String>Response headers with lower-case keys.
requestHtpioRequest?The request that produced it.
reasonPhraseString?Status text, e.g. OK.
isSuccessbooltrue for 200–299.

ResponseTypeenum

enum ResponseType { json, plain, bytes }

How the body is decoded. With json (the default), a body that isn’t valid JSON is returned as a String instead of failing. An empty body gives null.

fromJson vs decoderguide

Both turn the response body into your own type. Pick by the shape of the JSON.

JSON shapeUse
{ "id": 1, … }fromJson: User.fromJson
[ {…}, {…} ]decoder: (d) => [for (final e in d as List) User.fromJson(e)]
{ "data": [ … ], "total": 9 }decoder: (d) => Page.fromJson(d)
anything, no conversionleave both out; res.data is a Map, List or String

If fromJson receives a JSON list, the list is passed as {'data': list}. If your fromJson or decoder throws, the request fails with HtpioErrorType.parse.

Errors

HtpioErrorclass

final String message
final HtpioErrorType type
final int? statusCode
final HtpioResponse? response
final HtpioRequest? request
final dynamic originalError
final StackTrace? stackTrace

The only exception htpio throws, so you need just one catch. For a 4xx or 5xx reply, response.data holds the error body the server sent.

HtpioErrorTypeenum

enum HtpioErrorType { timeout, badResponse, cancel, connectionError, offline, parse, unknown }

Use it to show the right message to the user.

ValueHappens when
badResponseThe server replied with a status outside validateStatus (4xx/5xx by default).
timeoutThe request took longer than its timeout.
connectionErrorNo internet, DNS failure, refused connection, TLS error.
cancelA CancelToken was cancelled.
offlineOfflineMode knows the device is offline.
parsefromJson / decoder threw, or the data isn’t a T.
unknownAnything else. See originalError.

validateStatusguide

Decides which status codes count as success. Set it on the client for all requests, or on a single HtpioRequest.

Cancel & timeout

CancelTokenclass

CancelToken()
void cancel([Object? reason])
bool get isCancelled
Object? get reason
Future<void> get whenCancelled

Stops a request that is already running. One token can cancel many requests. A cancelled request throws HtpioError with type cancel.

Recipe: search as you typeguide

Cancel the previous search each time the user types, so an old, slow reply can never overwrite the new one.

Timeoutsguide

A timeout covers the whole request, from connecting to the last byte. Set a default on the client and override it per request.

Interceptors

HtpioInterceptorclass

abstract class HtpioInterceptor {
  HtpioClient? client;
  Future<HtpioRequest> onRequest(HtpioRequest request);
  Future<HtpioResponse> onResponse(HtpioResponse response);
  Future<HtpioResponse> onError(HtpioError error, HtpioRequest request);
}

Base class for your own interceptors. Override only the methods you need. onRequest can change the request before it is sent. onResponse can change the response. onError can recover by returning a response, or pass the error on by throwing it. client is set when you call addInterceptor; use client!.send(request) to send a request again.

AuthTokenInterceptorclass

AuthTokenInterceptor({
  String? token,
  String headerName = 'Authorization',
  String tokenPrefix = 'Bearer',
  FutureOr<String?> Function()? tokenProvider,
  Future<String?> Function()? onRefreshToken,
  List<int> refreshStatusCodes = const [401],
})
String? get token
void setToken(String? token)
void clearToken()

Adds Authorization: Bearer <token> to every request. With onRefreshToken set, a 401 reply triggers one token refresh and the request is sent again. If several requests fail at the same moment, they share a single refresh.

ParameterTypeWhat it does
tokenString?Starting token.
tokenProviderFunctionReads the token for each request, e.g. from secure storage. Used when no token is set.
onRefreshTokenFuture<String?> Function()Returns a new token. Return null to give up; the original 401 error is then thrown.
headerName / tokenPrefixStringFor APIs that use another header: headerName: 'x-api-key', tokenPrefix: ''.
refreshStatusCodesList<int>Which codes mean “token expired”. Default [401].

RetryInterceptorclass

RetryInterceptor({
  int maxRetries = 3,
  Duration baseDelay = const Duration(seconds: 1),
  bool useExponentialBackoff = true,
  List<int> retryableStatusCodes = const [408, 429, 500, 502, 503, 504],
  Set<String> retryMethods = const {'GET', 'HEAD', 'PUT', 'DELETE', 'OPTIONS'},
  bool Function(HtpioError error)? retryIf,
})
bool shouldRetry(HtpioError error, HtpioRequest request)
Duration delayFor(int attempt)

Retries failed requests, waiting 1 s, then 2 s, then 4 s. It retries timeouts, connection errors and the status codes listed. POST is not retried by default, so a payment is never sent twice.

ParameterTypeWhat it does
maxRetriesintRetries after the first attempt.
baseDelayDurationWait before the first retry.
useExponentialBackoffboolfalse waits 1×, 2×, 3× baseDelay instead.
retryMethodsSet<String>Add 'POST' only if your API is safe to repeat.
retryIfbool Function(HtpioError)Your own rule. Replaces the built-in checks.

HtpioLogInterceptorclass

HtpioLogInterceptor({
  bool requestHeaders = false,
  bool requestBody = false,
  bool responseHeaders = false,
  bool responseBody = false,
  void Function(String line) logPrint = <dart:developer log>,
  Set<String> hiddenHeaders = const {'authorization', 'cookie', 'set-cookie'},
})

Logs every request and response. Tokens and cookies are always shown as ***. Pass logPrint: debugPrint to send the lines to the Flutter console.

HtpioMiddlewareclass

abstract class HtpioMiddleware {
  HtpioClient? client;
  Future<void> beforeRequest(HtpioRequest request);
  Future<void> afterResponse(HtpioResponse response);
  Future<void> onError(HtpioError error);
}

Watches requests without changing them. Use it for analytics, timing or crash reporting. Throwing in beforeRequest stops the request. onError runs once, after all retries have finished.

Cache & offline

HtpioCacheclass

HtpioCache({Duration defaultTtl = const Duration(minutes: 5), int maxEntries = 100})

OfflineModeclass

OfflineMode({
  Duration checkInterval = const Duration(seconds: 5),
  Future<bool> Function()? connectivityChecker,
  Set<String> queueMethods = const {'POST', 'PUT', 'PATCH', 'DELETE'},
  int maxQueueSize = 100,
})
Stream<bool> get connectivityStream
Stream<Object> get replayResults
bool get isOnline
int get queuedRequestsCount
Future<void> refresh()

While the device is offline, requests fail immediately with HtpioErrorType.offline, so the user isn’t left waiting for a timeout. Saves (POST, PUT, PATCH, DELETE) are queued and sent automatically when the connection comes back. Each replayed result appears on replayResults.

ConnectivityHelperclass

static Future<bool> isOnline({String host = 'google.com', Duration timeout})
static Future<bool> isOnlineReliable({List<String> hosts, Duration timeout})
static Stream<bool> watch({Duration interval})
static Stream<bool> get onStatusChange
static Future<bool> isWiFiConnected()
static Future<List<NetworkInterface>> getNetworkInterfaces()

Quick internet checks you can call anywhere. On mobile and desktop they look up a host name (DNS). On the web they use the browser’s online status. isWiFiConnected is a rough guess; use the connectivity_plus package if you need an exact answer.

Platform supportguide

htpio is pure Dart with no native code, so there is nothing to set up per platform. It also works when your app is compiled to WebAssembly (WASM).

FeatureAndroid · iOS · macOS · Windows · LinuxWeb
Requests, interceptors, cache, mock, cancelYesYes
Uploads with fromBytes / fromStringYesYes
Uploads with fromPathYesNo (no file paths)
HtpioDownloadManagerYesNo: use ResponseType.bytes
ConnectivityHelper / OfflineModeDNS lookupBrowser online status

Upgrading from 1.1.xguide

1.2 doesn’t break existing code: the old methods still work but are marked deprecated. Switch at your own pace.

1.1.x1.2+
getRequest(endpoint: url, fromJson: f)get(url, fromJson: f)
postRequest(endpoint: url, data: d, fromJson: f)post(url, data: d, fromJson: f)
putRequest / deleteRequestput / delete
authToken: tAuthTokenInterceptor(token: t)
postSingleFileWithDataRequest / postFilesWithDataRequestpost(url, data: FormData.fromMap({...}))
request.execute()client.send(request)

Behavior changes: 4xx and 5xx responses now throw HtpioError instead of returning silently. RetryInterceptor and file uploads now actually work.
